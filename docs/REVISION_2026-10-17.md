# Revisión del proyecto · 17 de octubre de 2026

Se revisaron la estructura del proyecto, configuración y perfiles, rutas FastAPI, almacenamiento/autenticación, adaptadores, bucle de herramientas, proyectos, contenedores, lector web, relaciones, módulos de interfaz y pruebas. La base inicial aprobó 57 pruebas Python y la prueba Node. No hay repositorio Git en esta carpeta.

## Hallazgos y cambios

| Componente | Hallazgo | Resultado |
| --- | --- | --- |
| Agente | Ya existían búsqueda, memoria, ejecución y revisión, pero no un plan de dependencias exigido por el servidor. | Nuevo perfil Agente, `task_graph.py`, validación de DAG, estados observados y cierre de acciones al terminar. |
| Modelo | Llama 3.2 3B confundió formatos, produjo código incompleto y repitió acciones después del éxito en pruebas reales. | Contrato JSON explícito de Ollama, generación de argumentos por herramienta, comprobación sintáctica y límites. La fiabilidad general del modelo sigue sin demostrarse. |
| Archivos | Guardar archivos podía terminar como respuesta revisada sin comprobar la versión guardada. | Estado pendiente, manifiestos SHA-256 probados, persistencia en `project_checks` e invalidación en cada escritura. |
| Búsqueda | Se aceptaban los primeros tres resultados válidos sin clasificarlos por la consulta. | Hasta veinte candidatos, BM25 más cobertura del título, deduplicación de URLs y selección con diversidad de dominios. |
| Grafo de fuentes | Los pesos se presentaban solo como decimales aproximados. | Fracciones reducidas, tamaños de intersección/unión y umbral racional. Los ciclos y componentes describen ese grafo, sin validar hechos. |
| Evaluación | No había un corpus de ranking ni comparación reproducible. | Diez consultas ilustrativas repartidas en train/validation/test, etiquetas por URL y cuatro métricas offline. Incluye casos donde el ranking empeora. |
| Interfaz | Había actividad y grafo de fuentes. | La actividad muestra pasos, dependencias y estados del plan como texto seguro. |

No se modificaron las claves, los mensajes de usuarios ni las credenciales. Las pruebas usaron bases temporales. La inicialización futura de la aplicación añade una tabla para las comprobaciones, sin sustituir las tablas existentes.

## Evidencia y límites

La suite final aprobó **80 pruebas Python**, compilación de los módulos Python y la comprobación Node. Utiliza rutas/SQLite reales y modelo, red y Docker simulados. Se añadieron comprobaciones para ciclos, dependencias, permisos, resultados sin acciones, reintentos, versiones guardadas, estado entre turnos, sintaxis atómica, argumentos estructurados, métricas y ranking integrado. Node ejecuta los módulos reales con DOM/HTTP simulados; no acredita revisión visual en un navegador.

Las pruebas reales confirmaron texto y memoria con Ollama local y búsqueda con SearXNG. El perfil Agente completó un flujo mínimo de plan → archivo `saludo.py` → ejecución en Docker con `GRAFO_REAL_OK` → revisión final. También completó plan → `web_search` → `web_read`, leyendo un extracto HTTPS de `docs.python.org/3/library/graphlib.html`, con fuente marcada `page_extract` y grafo completo. Los intentos previos también registraron fallos de argumentos, sintaxis y presupuesto; no se consideran éxitos. Estos flujos mínimos aprobados no demuestran que cualquier tarea pueda resolverse.

El informe offline `evaluation/report.json` mide cinco casos de prueba sintéticos. Las etiquetas y extractos son ilustrativos, no una muestra representativa de internet. La mejora media observada convive con dos casos donde la fuente pertinente baja de posición. No se ajustaron parámetros mirando estos casos ni se entrenaron pesos.

## Trabajo posterior que necesita datos o alcance propio

- Recoger y revisar consultas reales antes de entrenar un clasificador, reranker o LoRA.
- Medir afirmaciones/citas y éxito de tareas completas; el ranking por sí solo no evalúa exactitud factual.
- Si se necesitan tareas largas, añadir puntos de reanudación y un tratamiento explícito de efectos ya ejecutados. El DAG actual pertenece a un turno; sus eventos se conservan, pero no se reanuda automáticamente.
- Evaluar modelos disponibles con el mismo conjunto de tareas. No se descargaron modelos nuevos ni se instalaron frameworks de entrenamiento.
- Revisar visualmente la interfaz en el navegador. No se cambiaron logo, video, estilos ni canal comunitario.
